# Local classification load test — November 2, 2026

The real exported LiteRT model ran through a single local Uvicorn process. Authentication and storage were fixtures; no cloud services or production accounts were used. Each case sent 128 requests. Every response was either valid classification output or an expected overload `429`; no transport or other response errors occurred.

These are short diagnostic runs on the developer machine, not measured Cloud Run capacity. Simulated personal models share the same bytes but occupy separate cache entries. The 64-user sequential workload deliberately cycles beyond the 32-entry cache. Warm cases reuse the preceding cache; cold cases clear it. Process memory can remain allocated between cases.

## Findings

- At zero synthetic storage delay, warm shared-model throughput stayed near 200 posts/s as concurrency increased from 4 to 16. At 64 concurrent requests, 45 of 128 requests were rejected. Additional concurrency did not create additional inference slots.
- Eight personal models warmed successfully and then incurred zero bundle downloads. Cycling through 64 personal models produced 128 misses and downloads in each sequential case, including the repeated pass. Each such case simulated about 1.01 GiB of bundle reads. This is an intentionally unfavorable access pattern, not a claim that all populations above 32 users will miss every request.
- Sampled RSS reached about 603 MiB in the first sequential 64-user case and 630 MiB on the repeated pass, compared with about 144 MiB for the warm shared model. These values include native/runtime overhead and allocations retained across cases; they are not exact per-model memory sizes.
- Adding synthetic storage delays caused substantial rejections even with warm models at concurrency 16. Metadata checks occur inside the classification semaphore, so their latency consumes the sole inference slot even on cache hits.
- Ten-post batches amortized storage-delay overhead but occupied the slot longer. The batch-at-concurrency-4 cases still returned 429s. Compare successful posts/s and feed responsiveness before changing the extension.

Recommended next deployment experiment: stage with concurrency 1, compare 2 and 4, and measure actual storage latency, realistic personal-model access, memory, and autoscaling cost. Do not extrapolate these laptop throughput numbers into an instance count. [Procedure and deployment decisions](../load-testing.md).

Validation: 49 existing server tests passed. The harness also validated successful response shapes and reported no unexpected statuses or transport failures across both runs. Production application code and deployment settings were unchanged.
